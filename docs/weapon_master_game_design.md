# ウエポンマスター 企画書(上流工程)

## 1. ジャンル定義

**インベントリ管理型 対戦ローグライク**
(参考ジャンル: Backpack Battles, Super Auto Pets の系譜 + 武器知識戦略)

バックパック(カバン)の限られたマス目に、ランダムに手に入る武器・素材を配置・合成し、
自動戦闘でCPUまたは他プレイヤーと戦う。武器ごとの特性を図鑑で理解し、
「何を拾い」「どう配置し」「何と合成するか」の意思決定の質を競うゲーム。

## 2. コンセプト・ビジョン

- **一言で言うと**: 「知る者が制す、カバンの中の戦争」
- **コアの魅力**: ランダム性(ドロップ)と必然性(知識に基づく最適配置)の両立
- **プレイヤー体験の理想形**: 序盤は手探りで配置するが、プレイを重ねるほど図鑑の知識が
  「この武器とこの素材を隣接させると相乗効果が出る」といった判断に直結し、上達が可視化される

## 3. コアゲームループ

1. ラウンド開始 → ランダムに武器・素材候補が数点提示される
2. プレイヤーはバックパック内の空きマス・配置ルールを見ながら1つを選択し配置
3. 配置による隣接効果・合成条件を確認し、必要なら手動合成
4. 自動戦闘フェーズ(PvP or CPU戦)で配置した装備が自動で機能し勝敗が決まる
5. 勝敗に応じて報酬(新武器候補・強化素材・通貨)を獲得
6. 1〜6を繰り返し、脱落 or 勝ち上がりでランが終了

## 4. 主要システム(概要)

### 4.1 インベントリ/配置システム
- グリッド式バックパック、マスの形状・サイズが武器ごとに異なる(テトリス的制約)
- 隣接マスによるシナジー(例: 剣の隣に砥石で攻撃力+)

### 4.2 武器図鑑・知識システム
- 未使用武器は情報が伏せられ、使用/遭遇して初めてデータが開示される「図鑑埋め」要素
- 図鑑閲覧画面で相性表・合成レシピを事前確認できる(戦略立案の起点)

### 4.3 合成/クラフトシステム(方式変更)

以前検討していた「バトル準備画面内で手動選択して合成する」方式は廃止し、
**戦闘後にバックパック内で接触しているマス同士を自動的に合成候補として扱う方式**に変更する。

- 合成の対象は、バックパック内で**マスが接触(隣接)している武器・素材の組み合わせ**
- 対戦(自動戦闘)を1回行った**後**に、接触状態にあった組み合わせが合成候補として判定される
- 合成候補になった武器は、**イラストの縁(ふち)が同じ色で光り、かつ対象同士を線で結ぶ**ことで
  プレイヤーに知らせる(縁の色+連結線の二重表現で視認性を高める)
- この「光る/線で結ぶ」演出は**新しい画面を用意せず、バトル準備画面のバックパック表示上の状態変化**として実装する
  (対戦→バトル結果ポップアップ→バトル準備画面に戻った際、接触状態にあった武器が
  光った状態・線で結ばれた状態で表示される)
- **合成の確定操作**: 合成候補が存在する状態で「バトル開始」ボタンを押すと、
  「合成する武器がありますが問題ないですか?」という確認ポップアップを表示し、
  プレイヤーの確認を取ってから合成を確定してバトルを開始する
- 合成が成立するかどうかは、隣接していた組み合わせが正規のレシピに合致するかどうかで判定する
  (レシピの内容は検証用ゲームデザイン仕様書を参照)

### 4.4 対戦(PvP)フロー
- 個人開発規模を考慮し、初期は**非同期対戦(相手の配置データと戦う)**を軸にする
  (リアルタイムPvPはサーバー負荷・同期コストが高いため後回し)

### 4.5 マッチ構造(対戦ルール)

- 1マッチは**全15戦**を上限とする
- **ライフ制**: ライフ5からスタートし、敗北するたびに1減る
- **勝利条件**: **10勝**でクリア
- 終了条件は「10勝達成」「ライフ0(5敗)」「15戦消化」のいずれか
- 詳細はバトル結果ポップアップ仕様書を参照

### 4.6 マニー経済(通貨バランス)

ゲーム内通貨「マニー」の増減ルール。

| 区分 | 内容 | 金額 |
|---|---|---|
| 増加 | 戦闘勝利 | **固定10マニー**/1勝あたり |
| 増加 | 武器売却 | 購入金額の**半額**(端数切り捨て) |
| 減少 | ショップでの武器購入 | 価格帯**1〜8マニー**(仮。ゲームバランスを見て調整予定) |
| 減少 | ショップの品揃え更新 | **固定1マニー** |

現時点では武器ごとの具体的な価格は未確定(1〜8マニーの範囲内で個別に設定予定)。
検証・プレイテストを通じて価格帯とバランスを調整する。

### 4.7 ランク制度(ランクマッチ)

ランクマッチにおける階級システム。8段階の階級を用意し、
ポイントを貯めることで階級が上がっていく仕組み。

**基本ルール**

- 階級は**全8段階**
- 勝利するとポイントが貯まる(**敗北してもポイントは減らない**。降格なし)
- 各階級には**昇格に必要なポイント数**が設定されており、**階級が上がるほど必要ポイントも増える**

**階級名称(仮)**

一般的な階級名称で仮決め。今後、世界観に合わせた独自名称への変更を検討してもよい。

| # | 階級名 | 昇格に必要なポイント(仮) |
|---|---|---|
| 1 | ブロンズ | 5pt |
| 2 | シルバー | 8pt |
| 3 | ゴールド | 12pt |
| 4 | プラチナ | 17pt |
| 5 | ダイヤモンド | 23pt |
| 6 | マスター | 30pt |
| 7 | グランドマスター | 40pt |
| 8 | チャレンジャー | 最高位(それ以上の昇格なし) |

- ポイントは**勝利した回数=ポイント数**として計算する(1勝=1ポイント、確定)
- ランクマッチ内の個々の対戦(1戦)に勝利するたびに加算される
- 昇格ラインの具体的な数値は、実装・プレイテストを通じてバランス調整予定

## 5. ターゲットユーザー

- Backpack Battles / Auto Battler系を遊んでいるPCコアゲーマー層
- 「知識で差がつく」対戦ゲーム(TCG、対戦格闘の起き上がり知識等)を好む層
- 短時間(1ラン15〜30分)で遊べるものを求めるSteamユーザー

## 6. 差別化ポイント(競合比較)

| 項目 | Backpack Battles系 | ウエポンマスター(本作) |
|---|---|---|
| 知識の役割 | プレイ経験で暗黙的に習得 | **図鑑を軸に明示的な学習要素として設計** |
| 対戦形式 | リアルタイム/非同期 | 非同期PvP優先(個人開発向けに現実的) |
| テーマ | ファンタジー雑多 | 武器・武具に特化し専門性を演出 |

## 7. MVPスコープ(個人開発向け)

**まず作るべき最小構成:**
- 武器10〜15種、素材5〜8種、合成レシピ10種程度
- グリッド配置システム(シナジー含む)
- CPU戦のみ(PvPは後続フェーズ)
- 図鑑UI(基本情報表示のみ、隠し要素は次フェーズ)

**あえて後回しにする要素:**
- 非同期/リアルタイムPvPのマッチング基盤
- シーズン制・ランキング
- 課金/コスメティック要素

## 8. 開発ロードマップ(案)

| フェーズ | 内容 | 目安 |
|---|---|---|
| Phase 0 | プロトタイプ(配置+戦闘の紙芝居レベル検証) | 2〜4週 |
| Phase 1 | MVP実装(CPU戦・図鑑基本版) | 2〜3ヶ月 |
| Phase 2 | 非同期PvP導入、図鑑の伏せ要素追加 | 1〜2ヶ月 |
| Phase 3 | コンテンツ拡充・バランス調整・Steamページ公開 | 継続 |

## 9. リスク・要検討事項

- **バランス設計の複雑さ**: 武器×素材×配置の組み合わせ数が爆発的に増える → MVPは意図的に少数種から開始し検証
- **非同期PvPの手触り**: リアルタイムでない対戦が「知識ゲー」として盛り上がるか要プロトタイプ検証
- **図鑑の伏せ方**: 情報を隠しすぎると新規参入障壁になる。チュートリアル設計と併せて検討要
