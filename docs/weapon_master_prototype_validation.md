# ウエポンマスター プロトタイプ検証計画

## 1. 目的

「配置(インベントリパズル)」と「知識(図鑑理解)」の組み合わせが
実際に面白いかどうかを、最小コストで最速検証する。
本格実装(Phase 1 MVP)に進む前の**Go/No-Go判断材料**を作ることが目的。

## 2. 検証すべき仮説

企画書で最も不確実性が高い要素を仮説として切り出す。

| # | 仮説 | 検証優先度 |
|---|---|---|
| H1 | グリッド配置+隣接シナジーは、事前情報なしでも直感的に触って理解できる | 高 |
| H2 | 「拾う武器を選ぶ」判断に、単純なランダム以上の戦略性を感じてもらえる | 高 |
| H3 | 図鑑で武器情報を事前に見られることが、配置判断の質を上げる実感につながる | 中 |
| H4 | 非同期PvP(相手の配置と自動で戦う)は「知識ゲー」として盛り上がる | 中 |
| H5 | 1ラン15〜30分というプレイ時間感覚は適切である | 低(後回し可) |

H1・H2は配置システムの根幹なので最優先。H4は開発コストが高いため、
紙・簡易ツールでの疑似検証を先に行う。

## 3. 検証範囲(最小構成)

MVPよりさらに絞った**検証専用の仮実装**とする。

- 武器: 5種(タイプが異なるものを選定し、シナジーの分かりやすさを重視)
- 素材: 3種
- 合成レシピ: 3〜5パターン
- 対戦相手: 固定パターンのCPU 2〜3体(強さの異なる構成)
- UI: 装飾なし、グリッド配置と戦闘結果表示のみで可

**作らないもの**: 図鑑の伏せ要素、PvP基盤、ビジュアル演出、サウンド

## 4. 検証方法

### 4.1 自己プレイ検証(最初のステップ)
- 開発者自身が10ラン程度プレイし、H1・H2について違和感がないか確認
- 「配置に悩む時間」「合成に気づく瞬間」が発生しているかを記録

### 4.2 少人数プレイテスト
- 5〜10人程度(ゲーム好きの知人・コミュニティ)に触ってもらう
- プレイ後に簡易アンケート/ヒアリングを実施

**確認する質問例:**
- 配置のルールは説明なしで理解できたか
- 「次に何を拾うか」を考える瞬間は楽しかったか
- 武器の情報をもっと知りたいと感じたか(H3の間接検証)

### 4.3 非同期PvPの疑似検証(H4)
- 実装せず、紙やスプレッドシート上で「配置A vs 配置B」の戦闘結果を
  手動シミュレーションし、結果に納得感・意外性があるかを確認
- 実装コストをかけずに"知識ゲーとして機能しそうか"の当たりをつける

## 5. 成功基準・撤退基準

| 判定 | 基準 |
|---|---|
| **Go(MVP実装へ進む)** | H1・H2で明確な手応えがあり、プレイテスト参加者の過半数が「もう一度遊びたい」と回答 |
| **要修正して再検証** | 配置ルールの理解に時間がかかりすぎる、シナジーに気づきにくい等、UI/ルール起因の問題が中心 |
| **No-Go(コンセプト再検討)** | ランダム性が強すぎて「選ぶ意味がない」と感じられる、戦略性を感じられないとの声が多数 |

## 6. スケジュール目安

| 週 | 内容 |
|---|---|
| 1週目 | 検証用の仮実装(グリッド配置+戦闘ロジックのみ) |
| 2週目 | 自己プレイ検証・調整 |
| 3週目 | 少人数プレイテスト実施・フィードバック収集 |
| 4週目 | 結果まとめ・Go/No-Go判断・MVP要件への反映 |

## 7. 検証後のネクストアクション

- **Go判定の場合**: 詳細ゲームデザイン仕様書(武器・レシピの具体数値)の作成へ
- **要修正の場合**: 該当する仮説のみ再検証ループを回す(全体を作り直さない)
- **No-Go判定の場合**: コアループ自体を見直し、企画書セクション2〜3に立ち返る
